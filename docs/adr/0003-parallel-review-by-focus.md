# ADR 0003: 観点別レビュー（focus）とウェーブ差分の先行レビュー（wave-review）

## ステータス

承認済み（Epic #143 / Task #147）

## コンテキスト

Epic #143 の柱の1つが**レビューの並列化とオーバーラップ**である。現在、Epic 末の一括レビューは
単一の evaluator が全観点（正しさ・可読性・過剰実装・セキュリティ・アーキテクチャ・テスト）を
1回で見ており、Epic の全差分を読む最も重い直列区間になっている。

これを (1) **観点別の並列レビュー**（4本同時起動）に分割し、(2) さらに**ウェーブ差分の
先行レビュー（wave-review）**を次ウェーブの実装と並行させることで、レビューの直列区間を
短縮したい。

このタスク（#147）は、その土台となる **evaluator 側の契約（モードと出力フォーマット）**を
用意する。run 側の並列起動・マージ手順は別タスクが担当する。

## 決定

### A. 観点（focus）の追加

evaluator の起動時に観点（`correctness` / `readability` / `over-engineering` / `security`）を
指定できるようにする。観点を指定して起動された evaluator は**自分の観点の指摘だけ**を出す。
観点未指定で起動された場合は**従来どおり全観点を見る**（後方互換）。

### B. モード `wave-review` の追加

既存の `epic-review`（`main...[epic-branch]`）・`delta-review`
（`[前回レビュー時のcommit]..[epic-branch]`）に加え、`wave-review`
（`[前回レビュー済みcommit]..[epic-branch]`）を追加する。あるウェーブが Epic ブランチへ
取り込まれた直後に、そのウェーブ差分だけを先行レビューできるようにする。wave-review の指摘は
その場で直させず、run 側が review issue として蓄積する。

### C. 出力 JSON の拡張

トップレベルに `focus`（観点未指定なら `"all"`）を追加し、`findings[]` の各要素にも `focus`
を持たせる。既存フィールド（`verdict` / `reviewed_commit` / `findings[]` の
`severity` / `title` / `location` / `detail` / `fix` / `task_ref`）は変更しない。
`adapters/codex/schemas/evaluator-verdict.json` も同じ形に更新する。

## 理由

- レビューは Epic 内で最も重い直列区間であり、観点分割は
  (1) 並列化できる（4本同時起動が可能になる）
  (2) 各 evaluator の読む範囲・チェックリストが減る（1観点だけを見るため）
  (3) 重複指摘が構造的に減る（観点を跨いだ指摘の重複提出が起きにくくなる）
- wave-review により、あるウェーブの差分レビューを次ウェーブの実装と並行させられる。
  Epic 末に一括でレビューする現行方式より、レビューの完了を前倒しできる

## トレードオフ

- **観点を跨いだ指摘（例: 可読性と設計の両方に跨る指摘）が落ちうる。** 各 evaluator は
  自分の観点だけを見るため、観点の境界にまたがる問題を単独では検出できない場合がある
- **4本ぶんのトークンを消費する。** 単一 evaluator による全観点レビューと比べ、
  起動回数が増える分だけトークン消費は増加する
- **run 側にマージ・重複排除の責務が増える。** 観点別に返る `findings[]` を統合し、
  同一 location の指摘を `focus` を併記して扱う処理が run 側に必要になる（別タスクの担当）

## 却下した代案

### Codex にも観点別の並列レビューを適用する案

Codex はサブエージェント専用の worktree を持たず、`codex exec` を子プロセスとして逐次起動する
構造のため、Claude Code のサブエージェントのような並列起動の手段がない（`core/instructions.md`
「Codex の位置づけ」で `lanes=1` 固定としているのと同じ制約）。無理に並列起動を実装すると
アダプタ間に大きな機能差が生まれ、実装・検証コストも見合わない。**Codex は引き続き単一
evaluator（観点未指定・全観点）のまま**とし、契約（`focus` フィールド・`wave-review` モード）
だけを共通化してスキーマの整合を保つ。

### 観点別チェックリストを本タスクで `core/references/` へ切り出す案

チェックリストの物理的な移動は、このタスクの本題（evaluator 側の契約追加）と混ぜると
差分が肥大化し、レビューコストが上がる。契約の追加と、チェックリスト本文の構造整理は
別タスクに分離した。このタスクでは既存の「レビューチェックリスト」節を観点ごとに参照する
対応表を追加するだけに留める。
